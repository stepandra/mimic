# Track F: drive, version watch, Workshop

## Interfaces

- `drive.parse` reads a SHA-256-pinned `drive.toml` and rejects option-like or malformed image names. `drive.docker_args` places `--` immediately before IMAGE so no image can become a Docker option; fixed nonroot, read-only, cap-drop, and resource limits remain in effect. `drive.run_with` permits a mock executor. `drive.run` invokes Docker only, with a monotonic five-minute wall deadline even for continuously chatty children. The Docker wrapper assigns a unique container name, force-removes that container on timeout, and reports the name if cleanup could not be verified. It does not claim capture coverage: the caller must connect an explicitly owned recorder container and compare actual request kinds with `expected_request_kinds`. No fallback executes the untrusted binary on the host.
- `watch.poll_with` takes an injectable HTTPS fetcher and clock. `watch.poll` uses `httpc` with TLS verification, one explicit registry URL, and npm's `dist-tags.latest` response. Observations are durable, debounce on *changed* versions, and `watch.enqueue` creates a PB run only when ready. A pending release uses a package/provider/version-specific run ID and goal: after a start→ack crash, retry acknowledges only a checkpoint matching that exact release and rejects colliding, unrelated runs. Polling never starts work automatically. CLI requires explicit URL and time (integer milliseconds).
- `workshop.start`, `next`, `advance`, `approve`, `resume`, `abandon`, `load`, `artifact`, `promote`, `promote_lab`, `rollback`, and `pointer` form the pipeline interface. `advance` runs **one** DAG stage via a trusted callback. It checkpoints `InFlight(stage)` and reserves estimated costly-stage tokens/oracle runs **before** invoking the callback, then checkpoints evidence only after validation. A callback error, crash, or invalid evidence leaves the outcome unknown and cannot automatically retry or refund; `resume` rejects it. The callback must perform the actual measurement, validate corpus coverage/lint/oracle/canary thresholds, redact sensitive data, and store a content-addressed artifact before returning `Evidence`. A model's proposed class/patch is not evidence. `BREAKING` pauses and writes `alerts/<run-id-hash>` for an operator. Neither `resume` nor promotion accepts it. A signed operator `abandon` records a reason and terminal failure, releases provider ownership, and permits a **separate** remediation run; it does not turn the old run into a success. MAJOR/MINOR/PO require signed `approve` before oracle; TRIVIAL still needs lint, oracle, and canary. `Budget` is checked before expensive callbacks; production adapters must also reserve tokens/runs in the shared quota ledger, which this local engine does **not** provide.

`Run` checkpoints, watch state, and immutable SHA-256 artifacts live under an explicit, private state directory. State paths reject symlinked root/feature directories and regular file reads reject symlink slots; new files use mode 0600 and state directories 0700. Each provider has one active run; a state-directory lock serializes transitions across VMs. Updates validate the active owner before changing a checkpoint, terminal release compare-deletes only its own pointer, and a start with no active pointer scans run checkpoints to reattach exactly one nonterminal orphan before allowing another run. An exact, unchanged start is idempotent; a terminal checkpoint left with a stale active pointer is reconciled on the next start. A per-run `effects/<id-hash>` guard spans reservation, callback, and result publication: concurrent advances cannot execute twice, and signed abandonment of an `InFlight` run fails while a callback is active. A crash during a callback leaves `InFlight` (not a retryable stage), while a killed VM can leave `.lock` or an effect guard behind: **verify that no writer survives before operator removal**; inspect actual external effects and use signed `abandon` to record the unknown outcome before a new run. Artifacts are written and synced to temporary files before being atomically published at the final digest path; partial final slots are rejected, not silently repaired. Atomic rename is used for checkpoints and registry pointers. **Directory fsync, power-loss durability, and cross-host/network-filesystem semantics remain unverified on this BEAM/macOS implementation**. The artifact hash uses SHA-256 rather than WORKSHOP.md's proposed BLAKE3; migration would require a versioned store.

Checkpoint decoding keeps Erlang's `[safe]` atom policy. The persistence FFI explicitly registers its finite run/evidence/stage vocabulary (rather than relying on a pipeline module having been loaded in the current VM) and validates the complete decoded term shape, including evidence, options, status, and budget counters. Malformed or unknown schema fails closed. This reads existing checkpoint terms without migrating or rewriting them; a new VM has been tested against previously persisted synthetic COMPLETE and BREAKING runs.

The production `promote` requires all completed gates, no `synthetic-` stage evidence, an operator-owned `MIMIC_PROMOTION_KEY`, and a hex HMAC-SHA256 signature over `provider || NUL || candidate_artifact_digest`. Set the key in the process environment, never in the repo. Public `rollback(dir, provider, signature)` authorizes before swapping and verifies the previous artifact still exists with its expected digest; absent/corrupt objects leave the current pointer unchanged. This key/signature mechanism does not implement git-compatible signed history or an external hot-swap notification. `promote_lab` is restricted to `synthetic-lab` and every evidence source must start `synthetic-local-lab`; it is **not** a production canary or signed promotion.

## Boundaries and unverified gates

No native CLI, Docker image/daemon, recorder, npm endpoint, subscription, real oracle, production SLO window, quota ledger, canary, macOS VM, or external signing infrastructure was exercised. Docker's bridge/`--network=container:` mode is not an egress firewall; configure recorder/network isolation outside this module. No secret-bearing data may be passed to `artifact`; the storage API does not inspect/redact content. Captures, acceptance, and canary outcomes must be measured by integrations, never inferred from successful Docker exit. The local tests use **synthetic** artifacts, a local emitting child for timeout, and mock callbacks only.

Workshop CLI can queue `run pb|po|co <state-dir> <id> <provider>` (PB also accepts `--goal <non-secret-text>`), inspect status/pointer, resume budget pauses, approve a human-gated run, abandon an unknown/BREAKING run, promote, and rollback. Queuing never executes a stage. Both CLI and public `approve(dir, id, reviewer, signature)` require a hex HMAC-SHA256 of `run_id || NUL || reviewer || NUL || candidate_artifact_digest` under process-only `MIMIC_REVIEW_KEY`; the candidate digest is in the run's Hypothesis/Author evidence. `abandon(dir, id, reason, signature)` requires `run_id || NUL || "abandon" || NUL || reason` under that key. `rollback` requires `provider || NUL || "rollback"` under `MIMIC_PROMOTION_KEY`. `promote` uses the candidate signature described above. CLI has no arbitrary stage-result flags. Key values must be provisioned outside the repo. These HMACs are a local operator gate, not a multi-user identity/authentication system; a production control plane needs authenticated reviewer identity, authorization, and audit.

The root `gleam test` gate was blocked by the unrelated absent `mimic/recorder/tls` module and an unrelated `policy_test` type import in this parallel snapshot. An isolated F-only Gleam harness compiled these three modules and passed 22 synthetic/local tests, including fresh-VM checkpoint loads, malformed schema rejection, a hard-killed stage worker, and a continuously emitting local child. No Docker daemon or privileged container was used.
