## Architecture and compiled public API

```gleam
// mimic/containment/policy
Backend(executable: String, socket: String)
Network(bind_ports: List(Int), connect_ports: List(Int))
Limits(wall_ms, lease_ms, memory_mb, pids, work_mb, output_bytes)
Request(image, executable, args, network, limits)
authorize(Request) -> Result(Plan, String) // Plan is opaque

// mimic/containment
execute(Backend, Plan) -> Result(Receipt, String)
cli(List(String)) -> Result(String, String)
```

`execute` runs the fixed synthetic fault suite **fresh**, against the same local
immutable image and explicit backend, before creating the requested target.
Caller-supplied status, fixture reports, a persisted "qualified" flag and public
discovery are not authorization. The lower-level `docker` module is an internal
OS integration seam, not an alternative qualifying execution API.

1. An explicit absolute Docker executable and Unix socket select a local
   control plane. There is no Docker-context or account discovery. The CLI
   receives a cleared environment and `/nonexistent` HOME/DOCKER_CONFIG.
2. Require a Linux daemon and an already-local immutable `sha256:<64 hex>` image.
   Images declaring Docker volumes are rejected. Never pull or install.
3. Create an inert, uniquely named container: no host mounts, host sockets,
   published ports, host networking/PID/IPC sharing, privileged mode, healthcheck,
   restart or runtime logs. Root is read-only; only bounded private tmpfs state
   exists. Docker memory/swap, CPU, PID and core/FD bounds are configured;
   the mandatory launcher must install target CPU/file/FD limits. Output is bounded.
4. Attach stdin/stdout. The caller's BEAM process renews the owner lease; no
   detached host watchdog can renew after that caller dies.
5. The trusted BEAM VM is PID1. It checks its namespace, root filesystem,
   capabilities and no-new-privileges. An initial valid lease is required before
   spawning a target. A kernel launcher must prove TCP-port/filesystem support
   before any target is spawned.
6. Targets use UID10001 and zero capabilities, distinct from the UID0 owner.
   The owner retains only SETUID/SETGID for that one identity transition.
   No SYS_ADMIN, NET_ADMIN, privilege escalation or Docker socket is available.
7. Lease EOF, renewal expiry, absolute timeout, early leader exit, launch/output
   failure all finish PID1. Linux then kills **every task in the PID namespace**,
   including double-forked and `setsid` descendants. Process groups are not a
   qualifying fence.
8. A dedicated executable wrapper forces namespace shutdown even if final report
   I/O stalls. It is not a feature module that halts its caller's VM.
9. The live parent confirms `State.Running=false` and `State.Pid=0`, force-removes
   the exact container ID and obtains a successful daemon listing proving the
   exact name absent. Generic `inspect` failure is never evidence of absence.
   Cleanup failure overrides both success and target failure.

The parent may die before cleanup. The namespace lease/deadline is deliberately
independent of that cleanup. A stopped container object may remain and must be
removed explicitly by its returned ID/name; no unverified cleanup is a pass.
There is no guarantee against a malicious Docker daemon/kernel/operator; those
are trusted parts of the boundary.

## Network is not merely `--network none`

The outer namespace has only loopback and no route to the host or Internet.
Inside it, a **mandatory separate OS launcher** must restrict TCP bind/connect
to the finite port sets in `Network`. UDP, raw and Unix-domain sockets must be
denied. A target cannot access the root owner's lease channel, credentials or
namespace-control facilities.

Neither Seatbelt's process-group cleanup nor filesystem-only util-linux
`setpriv --landlock-*` satisfies this contract. In particular, reviewed
util-linux 2.41.2/2.42 only implements Landlock filesystem rules, not TCP ports.
No imaginary `setpriv` network flags or all-loopback waiver is used.

The required OS primitive is `/containment/launch`. The operator has approved
its implementation in **Zig**, restricted to Linux OS setup and `execve`; scenario
authorization and process-tree lifetime remain Gleam-owned. The source and
build entry point live under `scripts/containment/launcher/`. If the artifact
is absent, incompatible, denied or fails its check, the owner returns failure
before target spawn. Kernel qualification is recorded separately from compilation
and does not follow from this approval.

### Required launcher contract (not measured evidence)

```
/containment/launch --check
# exit 0 and exactly: mimic.containment-launch/v1\n

/containment/launch \
  --bind-ports 39003 --connect-ports 39001 \
  --cpu-seconds 40 --file-bytes 8388608 --no-files 256 \
  -- /usr/local/bin/python3 /qa/containment_faults.py baseline
```

`-` means an empty port set. The launcher must fail, without execing the target,
when any rule or required kernel operation cannot be installed. Minimum duties:

- Landlock filesystem and TCP bind/connect rules, no silent ABI downgrade;
- finite image-runtime read/execute roots, writable `/work` and `/tmp` only;
  no read/execute permission for `/containment` or `/boundary`;
- read-only per-process `/proc/self` and bounded cgroup metadata needed by tests,
  never the owner FD/lease/memory space;
- socket-family/type enforcement for TCP only, including alternate socket
  syscalls on supported architectures; namespace/network-control syscalls denied;
- core=0, CPU=40s, file=8MiB, FD=256 hard limits;
- close inherited descriptors except private target stdio, stdin `/dev/null`;
- clear supplementary groups, set GID/UID10001, retain no capabilities, preserve
  no-new-privileges, set private cwd/home and umask;
- exact environment: PATH=/usr/local/bin:/usr/bin:/bin, HOME=/work/home,
  TMPDIR=/tmp, LANG=C.UTF-8, TZ=UTC, LD_LIBRARY_PATH=/usr/local/lib;
- `execve` an argument vector, never shell-text interpolation.

Kernel/image provenance and measured probes, not `--check` alone, qualify this
dependency. General live egress, secrets and cost/token/request budgets remain
F04's separate contract. F02's current public request is public/synthetic-only.

## Actual synthetic selftests implemented

Explicit opt-in, never broad test discovery:

```sh
sh scripts/containment/focused.sh
sh scripts/containment/run.sh selftest \
  /absolute/path/to/docker /explicit/operator-owned/docker.sock sha256:IMAGE_ID
```

The image must contain the boundary and the fixed harmless probe. The selftest
owner starts real listening TCP fixtures on 39001 (allowed) and 39002 (denied).
The target must connect successfully to 39001 and receive the synthetic marker,
but receive a permissions error connecting to the listening 39002. Unreachable
hosts/unused ports are not negative containment proof. TCP bind 39003 is allowed;
39004, UDP and Unix sockets must fail. Filesystem, owner-FD access, fresh
environment, UID/caps/no-new-privileges and actual cgroup/rlimits are checked.

Lifetime scenarios first observe a real descendant using Docker `top`, then:

| Case | Required observed result |
| --- | --- |
| Parent SIGKILL | Kill a separate host BEAM coordinator by its owned handle; observe exit 137; namespace stops within bounded lease window, without that coordinator's `finally` |
| Lost lease with live pipe | Send one lease then keep attachment open without renewals; owner exits 125 with `lease_expired` |
| Timeout | Continue renewals; absolute owner deadline exits 124 |
| Early leader exit | Ordinary child ignores TERM and outlives leader; namespace is still stopped |
| `setsid` | Observe a different SID AND reparenting after the intermediate child's exit, not just a marker; namespace still stops on early leader exit |
| Cleanup failure | Actual malformed Docker removal request fails; stopped namespace confirmed; failure cannot be converted to success; separate normal removal is explicit test recovery |

No adversarial target is launched on the host. The SIGKILL companion on the host
is only the compiled, bounded Gleam lease coordinator. It has no provider logic
and never executes a requested native binary there.
Descendants deliberately retain their target's private stdout/stderr pipes;
an inherited output FD must not defer the owner's early-leader-exit fence.

## Packaging, integration seams and remaining prerequisites

`package.sh <absolute-approved-linux-launcher-artifact>` stages only compiled
boundary BEAMs, the executable wrapper, launcher and synthetic probe under
ignored `build/containment/image-context`, with input hashes. It refuses to
overwrite an existing context. It neither builds nor contacts Docker.
The new Dockerfile is a repackaging recipe, not approval to acquire/build/use
images; it has no default base or install/download command. Target/fixture/
shipment artifact ownership remains with F03/F30–F38.

Parent-approved minimal shared hooks (**implemented**):

1. `qa.offline` requires explicit `--docker-path` and `--docker-socket`, invokes
   one full contained harness session via the thin `bridge.py` adapter, and
   retains acquisition, workflow reports and the unchanged validator. It never
   invokes the historical `container_args` fixture or legacy cleanup fallback.
2. `harness.containment` requires the root-owned 0444 owner marker in sticky
   tmpfs. The fixture subclass binds 39011 and gateway uses 39012; fixture source
   logic is unchanged. The selected public shipment hash is compared with the
   image's embedded shipment before gateway/native children. No host mount is used.
3. `reference_sandbox.start` refuses the Seatbelt-only launch. Its policy/probe
   remain source evidence; F03 must call the compiled F02 session seam rather than
   replace `Popen` with an incompatible synchronous result.

The old native-client Dockerfile/receipts do not magically acquire this owner or
port filter. Native/CPA/live execution stays blocked until repackaged pinned
artifacts and the actual F02 selftest pass are bound by F01's acceptance contract.
No root CLI admission is required to use the standalone executable seam.
