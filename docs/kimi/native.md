## Integration contract

`mimic/providers/kimi/models.registration(id)` returns a runtime model for native **Responses** (`api_key` or `oauth`, buffered or streaming) and buffered **Chat**. The gateway lists explicitly enabled models per account. Capabilities are model-level; both gateway dispatch and request preparation reject Chat streaming before I/O. Chat uses `request.prepare_at` and `adapter.collect`, not a Responses-to-Chat conversion.

The runtime-selected `contracts.Context` supplies the account, credential, and exact origin. `request.prepare(context, request)` uses the CPA coding path `/coding/v1/responses`; `request.prepare_at(base_path, context, request)` accepts a configured path-only prefix such as `""` for `/v1/responses` or `"/operator/kimi"` for `/operator/kimi/v1/responses`. `request.http_at(fn(context) -> Result(base_path, Failure), ca_file)` lets the gateway look up the path **by the selected `context.account`**, not by first configured account. It never changes origin; path traversal, authority, query, fragment, and percent escape are rejected. The runtime transport verifies TLS and prevents redirects. Loopback HTTP is permitted for synthetic fixtures only.

`request.rejection` treats 401 as a known credential rejection and 429 as uncertain quota; 429 is **not replayable**. `adapter.collect` validates buffered Responses JSON with the shared Responses decoder (Chat with shared OpenAI decoder); `adapter.run` validates Responses SSE through the shared HTTP/stream codec. It does not create an independent codec or manager. Response bodies and token-bearing request plans are not diagnostics/captures for storage.

`oauth.Config(domain, device_url, token_url, device_id)` requires explicitly approved exact `.com`/`.ai` HTTPS OAuth URLs, or paired loopback HTTP test URLs. The gateway stores a secret-free `Config` with blank `device_id` after `oauth.validate_endpoints`; login/import bind private device identity before `oauth.validate` or `oauth.import_material`. `oauth.start` and `oauth.poll` perform only injected `Send(TokenPlan) -> Result(TokenReply, String)` calls; no default live transport or browser launch. The foreground gateway enrollment loop supplies bounded polling, then persists through `runtime_store`. `oauth.import_material` requires nonempty access/refresh and a positive explicit expiry (it accepts an expired grant for runtime refresh); it supplies the runtime's private OAuth envelope with domain, device identity and token URL. `oauth.refresher(config, send)` binds device ID from each private grant, not from global config. Runtime owns private 0600-file persistence in a 0700 directory, refresh singleflight/fencing, retries and account lifecycle. **These files are not encrypted.** Persist rotation before using a new access token. The callback rejects identity/endpoint mismatches and ambiguous refresh outcomes. Secrets must never enter captures, logs, metrics or model packs.

## Deliberate gaps and gates

- Request schemas are deliberately narrow: text-only Responses input (`input` string, basic fields) and basic text-only buffered Chat. Unknown options, native tools, multimodal content, thinking controls, temperature transforms, previous-response continuation, compact, Claude delegation, Chat SSE, and WebSocket fail closed or remain unregistered. CPA's richer transforms are **not** implied by model metadata.
- Device token `expires_in` must be a positive integer here; CPA parses a numeric float. An upstream fractional value is rejected rather than rounded. No live OAuth grant or inference endpoint has been called.
- No TLS fingerprint, user-agent/build version, host/device model or quota availability is claimed. The configured device ID is passed for OAuth; no CLIProxyAPI identity is spoofed.
- Provider unit tests are synthetic request/token plans. `scripts/smoke-http-providers.py` also exercises actual Mist ingress and fresh CLI processes for API-key and both OAuth domain configurations: selected account origin/path/auth/device identity, buffered Chat/Responses, SSE prefix/terminal, refresh/persist/restart, configured device enrollment, unsupported-feature denial and key revocation. Endpoints are synthetic localhost; this is not live domain verification or CPA differential parity.
