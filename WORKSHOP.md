# WORKSHOP (Мастерская) — CI для новых бинарей и подписок
Дополнение к DESIGN.md (MIMIC) · v0.1 · 2026-09-14
Рабочее имя: Workshop (мастерская). Radar из DESIGN.md §8 — исследовательский контур;
Workshop — его индустриализация: те же recorder/corpus/differ/oracle/canary, но
собранные в декларативные пайплайны с триггерами, гейтами, бюджетами и промоушеном.

---

## 1. Идея одной фразой

GitHub Actions, но единица сборки — не код, а **пара (бинарь CLI × подписка)**.
«Коммит» — выход новой версии бинаря или заведение новой подписки. «Билд» — корпус
захватов + кандидат персоны. «PR» — drift report + дифф персоны на ревью. «Мерж в main» —
промоушен персоны в прод-реестр. «Тесты» — драйвы и oracle. «Откат» — rollback указателя
в реестре персон.

Три потока (pipeline templates):

| Пайплайн | Триггер | Что делает | Частота |
|---|---|---|---|
| **PB** persona-bump | новая версия известного клиента | авто-дифф старой/новой персоны | часто (недели) |
| **PO** provider-onboard | новый провайдер/тип подписки | авторинг персоны v0 с нуля | редко (месяцы) |
| **CO** cred-onboard | новый аккаунт/подписка известного провайдера | логин, burn-in, ввод во флот | по мере покупки |

## 2. Общая схема

```
 ТРИГГЕРЫ                     ПАЙПЛАЙН (стадии = DAG)                      ВЫХОД
 ────────                     ─────────────────────                       ──────
 version-watch ─┐
 schedule      ─┤   ┌─acquire─►drive-capture─►diff─►hypothesis─►lint─┐
 manual        ─┼─► │  (PB)                                      ├─► [G2] oracle
 quota-anomaly ─┤   │                                            │      │
 alert        ─┘   │                            [G1: human review]◄─┘      ▼
                ─► │  (PO) intake►auth-capture►census►author►lint ──►  canary ─► [G3] ─► PROMOTE
                ─► │  (CO) login►verify►burn-in►enroll ──────────────►  (пробация)  (реестр, hot-swap)
                   └───────────────────────────────────────────────
 РАННЕРЫ: одноразовые VM (бинарь = недоверенный код) ─ egress через MITM-recorder
 БЮДЖЕТ: каждый oracle/canary run жжёт подписочные токены → бюджет-гард
 АРТЕФАКТЫ: content-addressed, immutable: бинарь, корпус, drift report, персона, ревью
```

---

## 3. Триггеры

| Триггер | Источник | Пайплайн | Политика |
|---|---|---|---|
| version-watch | реестры пакетов (npm `@anthropic-ai/claude-code`, `@openai/codex`, `@google/gemini-cli`, …), GitHub releases | PB | debounce 2ч (два релиза в день → берём последний); debounce-окно мержится |
| schedule | cron | PB-lite | ночной smoke: прогон драйвов на текущей версии — ловит server-side дрифт без нового бинаря |
| manual | оператор | PB/PO/CO | с параметрами (версия, провайдер, creds) |
| quota-anomaly | прод-метрики (acceptance-rate, 4xx-словарь, TTFT) | PB-lite | дифф против последнего корпуса: «сервер изменил поведение при том же клиенте» |
| cred-add | оператор / флот | CO | batch: несколько аккаунтов → параллельные CO-раны |

Приоритеты: quota-anomaly (прод горит) > version-watch > schedule. Один провайдер —
не более одного активного пайплайна (загрязнение корпуса и гонки за бюджет).

## 4. Пайплайны

### 4.1 PB — persona-bump (новая версия известного клиента)

| # | Стадия | Вход | Выход | Гейт/правила |
|---|---|---|---|---|
| 1 | acquire | версия | бинарь-бандл: pinned tarball/release, хэши blake3, размер, дата | источник верифицирован (реестр/TLS), бандл immutable |
| 2 | drive-capture | бандл, драйвы, sacrificial-кред | corpus-снапшот: TLS-trace, h1/h2 фреймы, заголовки с исходным кейингом/порядком, тела (zstd, обрезаны) | coverage-чеклист закрыт (см. §5), иначе run = insufficient-coverage (fail, не flaky) |
| 3 | diff | corpus vs baseline (персона в прод) | drift report (машиночит.) + human-readable дифф | — |
| 4 | classify | drift report | класс: TRIVIAL / MINOR / MAJOR / BREAKING | правила в §4.1.1 |
| 5 | hypothesis | drift report + персона vN | кандидат vN+1 (машинная правка TOML) | для TRIVIAL — авторевью пропускается (auto-merge) |
| 6 | lint | кандидат | отчёт линта | запрещённые комбинации бет, обязательные заголовки, совместимость transport-профиля |
| 7 | oracle | кандидат + corpus-sample | oracle report: классы ответов upstream, TTFT, SSE-грамматика | бюджет-гард (§7); порог acceptance |
| 8 | canary | промо-кандидат | метрики окна | SLO-окно: 4xx-дельта, TTFT-дельта, мин. длительность/объём |
| 9 | promote | подписанный кандидат | запись в реестре, hot-swap | G3; откат = возврат указателя |

#### 4.1.1 Классификация диффа (это «правила авто-мержа» Workshop)

| Класс | Признак | Маршрут |
|---|---|---|
| TRIVIAL | только строковые версии (UA, x-stainless-package-version, originator-версия) | авто-патч персоны, авто-промоушен через сокращённый oracle (sample 10%) |
| MINOR | новые опциональные заголовки/беты, не ломающие старые ответы | ревью одним взглядом, полный oracle |
| MAJOR | изменился порядок/состав обязательных бет, новые request-kind, изменения identity | обязательное human-ревью + полный oracle + расширенное canary |
| BREAKING | upstream отвергает replay старой персоны на новом бинаре (prod уже сломан) | приоритетный ран, откат невозможен — только форвард; алерт в прод |

Замер из аудита CLIProxyAPI: самый частый дрифт — именно версии строк (у CPA сейчас
пины 2.1.258/0.112.1 против npm 2.1.270/0.125.0, и это НЕ сломало прод — значит класс
TRIVIAL/MINOR). Автоматизация TRIVIAL — 80% ценности Workshop при 20% усилий.

### 4.2 PO — provider-onboard (новый провайдер/тип подписки)

| # | Стадия | Вход | Выход | Гейт |
|---|---|---|---|---|
| 1 | intake | форма оператора: endpoints, auth-тип, ожидаемые модели | карточка провайдера | — |
| 2 | auth-capture | нативный CLI под MITM | OAuth-паспорт: authorize/token/refresh URL, client_id, redirect, scopes, PKCE-параметры, формы токенов, TTL, header-order профиля refresh | login-флоу воспроизводим headless |
| 3 | census | драйвы на sacrificial-кред | corpus по всем request-kind + карта rate-limit заголовков (пассивно, из ответов) | coverage-чеклист; деликатные пробы 429 — опционально и отдельно (§7) |
| 4 | author | corpus + паспорт | персона v0 (TOML) + cred-actor шаблон + квота-словарь | human-ревью обязательно |
| 5 | lint / oracle / canary | как PB | | |
| 6 | enroll-templates | персона, шаблоны | флот-конфиг провайдера; CO для первого боевого креда | — |

Особенность: PO — единственный пайплайн, где человек — обязательный соавтор
(первичная персона = интерпретация корпуса). Всё остальное — механика.

### 4.3 CO — cred-onboard (новая подписка известного провайдера)

| # | Стадия | Вход | Выход | Гейт |
|---|---|---|---|---|
| 1 | login | кред-канал (headless-браузер или нативный CLI login-флоу) | токены в auth-dir (0600/age), identity (account_uuid, device pool) | login сам нативен: MITM на login-флоу включён — OAuth-хендшейк тоже фингерпринтится upstream'ом |
| 2 | verify | токены | профиль/roles-проба, снапшот квот (5h/7d окна, tier) | identity-проба без аномалий |
| 3 | burn-in | кред | градуированная нагрузка 10→100 запр/день (лестница 3–7 дней), пассивное наблюдение | нет 429/таймаут-аномалий, latency в энвелопе |
| 4 | enroll | — | флот: вес, sticky-init, egress-IP, ledger-инициализация | egress-IP не пересекается с другими кредами того же провайдера |
| 5 | probation | 72ч в прод с малым весом | метрики | авто-алерт при отклонении; после — полные права |

CO массовый (10 аккаунтов = 10 параллельных ран, каждый на своём egress-IP;
логины размазываются по часам — не 10 логинов за минуту с одного IP).

## 5. Драйвы — «тесты» этого CI

Драйв = детерминированный сценарий, гоняющий **настоящий бинарь** через recorder.
Аналог тест-кейса: фиксированные входы → ожидаемая форма запросов.

Библиотека (стартер):

| Драйв | Какой request-kind покрывает | Заметки |
|---|---|---|
| drive.chat | основной turns, main-сессия | system-префикс, metadata.user_id |
| drive.subagent | spawn сабагента | X-Claude-Code-Agent-Id, betas-подмножество |
| drive.count_tokens | count_tokens | беты без extended-cache-ttl |
| drive.helper | haiku-helper зонд | helper-профиль (6 измеренных форм у CPA) |
| drive.mcp | MCP tool call | tool schema формы |
| drive.stream/.nostream | транспорт | Accept/Accept-Encoding ветки |
| drive.long | длинный контекст | cache_control, 1m-беты |
| drive.toolfail | retry-пути | x-stainless-retry-count ≠ 0 |
| drive.refresh | истечение токена | refresh-флоу, header-order |
| drive.resume | session resume | session continuity, sticky identity |
| drive.entrypoint-<X> | cli / sdk-cli / vscode / … | allowlist-карантин новых entrypoint |

Свойства драйвов:
- Входы зафиксированы сидами (промпты, тулзы, модель) — корпус сравним между версиями.
- Промпты крошечные, max_tokens мал: цель — форма запроса, не качество ответа.
- Драйвы версионируются вместе с персонами: у персоны — свой coverage-чеклист
  (request-kind × betas-условия × model-class). Coverage = требование к стадии
  drive-capture, недобор = fail (не flaky).
- Новые драйвы пишутся при каждом MAJOR-диффе (если появился новый request-kind —
  сначала драйв, потом персона; драйв = регрессионный тест на будущее).

## 6. Раннеры и песочница

- Бинарь CLI = **недоверенный код** (node-бандл исполняет произвольные скрипты,
  MCP-серверы и т.п.): только одноразовая VM/контейнер, никогда не хост.
- Пресет раннера: macOS arm64 образ (нативная среда для большинства CLI; OS-профиль
  из UA не врёт), автоустановка CA-recorder'а, HTTPS_PROXY на recorder, cleanup после рана.
- Cert-pinning у клиента → раннеровский fallback: pcap-режим (тела недоступны,
  corpus деградирует до TLS/timing-осей — пайплайн помечает это в артефакте).
- Egress workshop-пула IP отделён от прод-кред IP: sacrificial-аккаунты не должны
  светиться с адресов прод-аккаунтов того же провайдера.
- Проду не место в Workshop: oracle/canary ходят через основной egress-слой MIMIC,
  но на меченых (canary) кредах.

## 7. Бюджет-гард (квоты — деньги)

Каждый oracle/burn-in/canary run жжёт подписку. Правила:

1. Бюджет per-pipeline: N запусков oracle/час, M токенов/день на sacrificial-кред.
2. Адаптивный oracle: TRIVIAL — sample 10% корпуса; MAJOR — полный replay.
3. Тайминг: тяжёлые прогоны — в окна низкой прод-нагрузки (ночь), чтобы burn
   sacrificial-квоты не коррелировал с пиками прод-кред (энвелоп потребления).
4. Деликатные пробы (намеренный 429 для изучения reset-заголовков) — отдельно
   отключаемый флаг, по умолчанию off; пассивное обучение из прод-ответов — норма.
5. Весь расход пишется в общий quota ledger вместе с продом (Workshop — «тень»-клиент
   флота, у него свои строки в ledger).

## 8. Артефакты и реестр

Content-addressed (blake3), immutable, ротация по возрасту:

- бинарь-бандл (pinned версия + хэши)
- corpus-снапшот (по правилам приватности DESIGN.md §13)
- drift report (машиночит. + human diff)
- кандидат персоны + запись ревью (кто утвердил, комментарий, откат)
- oracle report, canary-метрики окна
- промоушен-запись (подпись, указатель в реестре)

Реестр персон = git-совместимое хранилище (персоны уже TOML): история, теги
(stable/canary), подписи. Промоушен — атомарный swap указателя; откат — возврат.

## 9. Гейты и промоушен

| Гейт | Тип | Критерий |
|---|---|---|
| G1 human | ревью drift report + дифф персоны | обязательный для MINOR+; TRIVIAL — авто |
| G2 oracle | авто | acceptance ≥ порога (классы ответов не хуже baseline; новые 4xx-словари = стоп) |
| G3 canary | авто | окно T ≥ 2ч и N ≥ X запросов; 4xx-дельта < 1%, TTFT-дельта < 10% к baseline |
| G4 promote | авто+подпись | G2∧G3; запись подписана; авто-откат при SLE-нарушении после промо (rollback-pointer) |

SLO-параметры — конфиг per-provider, не глобальные.

## 10. Изоляция и безопасность

- Sacrificial-подписки для capture/oracle (2–3 аккаунта на провайдера), физически
  отдельные от прод-кредов: identity, egress-IP, окно потребления.
- Раннеры не держат прод-кредов никогда; токены sacrificial-кредов — только на
  раннерах, шифруются, вычищаются после рана.
- Corpus может содержать данные аккаунтов → те же правила редукции/обрезки, что в проде.
- Бинари вендорятся в бандл (никаких postinstall-скачиваний в рантайме — контраст
  с runtime-скачиванием панели у CPA).

## 11. Флейки и отказы

| Отказ | Обработка |
|---|---|
| сеть раннера/ upstream 5xx в oracle | различать классы: 5xx ≠ acceptance-fail; retry с backoff, максимум 2 |
| insufficient-coverage | fail рана, не flaky; драйв-инженерия отдельно |
| cert-pinning в MITM | авто-fallback в pcap-режим, корпус меченый degraded |
| гонка версий (2 релиза подряд) | debounce, берётся последний; корпус от отвергнутой версии — в архив |
| contamination (человек работал в sacrificial-аккаунте во время capture) | запускам capture — монопольный слот аккаунта; нарушение = реран |
| budget exhausted | пайплайн pause с алертом, не fail: продолжится в следующем окне |
| G3 не сходится (никак не проходит canary) | авто-откат + тикет оператору; прод живёт на старой персоне |

## 13. Открытые вопросы

1. Драйвы на реальных MCP/инструментах: сколько детерминизма достаточно, чтобы корпус
   был сравним? (риск: слишком синтетические промпты = форма запросов отличается от прод).
2. Сколько sacrificial-аккаунтов на провайдера достаточно (2–3?) и ротация их identity.
3. Раннер-инфраструктура: локальные VM (Mac Studio — он же и раннер) vs облако;
   macOS-образ для PO на не-mac провайдерах.
4. Формат G1-ревью: отдельная мини-панель (drift report viewer) или PR в git-репо персон.
5. Пороги G2/G3: стартовые значения и калибровка по первым 10 пайплайнам.
