# AUTOPILOT — автономный оператор Workshop на локальной модели
Дополнение к WORKSHOP.md · v0.1 · 2026-09-14
Рантайм: Qwen 27B abliterated, llama-server на Mac Studio (OpenAI-compatible endpoint),
грамматико-ограниченная генерация (GBNF/json_schema).

---

## 0. Принцип одной фразой

**Модель решает — машина проверяет.** Workshop-пайплайн остаётся детерминированным
механизмом (DAG стадий, гейты, бюджеты — см. WORKSHOP.md); модель не «управляет всем»,
а вызывается на точечных микро-задачах внутри стадий. Каждая её заявка
машинно-проверяема, каждая галлюцинация попадает в ловушку по конструкции:
плохой патч персоны умирает в oracle, плохая классификация — в lint,
непроверяемая проза — в шаблонном отчёте.

Человек появляется дважды: «вот бинарь + подписка» в начале и «подтверждаешь?» в конце.

## 1. Разделение труда

| Слой | Кто | Что | Может галлюцинировать? |
|---|---|---|---|
| Оркестрация | Workshop-движок (Gleam) | стадии DAG, гейты, бюджеты, промоушен, откат | нет — код |
| Исполнение | драйвы, recorder, oracle, canary | захват, replay, метрики | нет — детерминированные прогоны |
| Суждение | Qwen 27B | интерпретация диффов, патчи персон, авторинг драйвов, диагностика | да — и потому каждый выход валидируется |
| Подтверждение | человек | G1/G4 (промоушен) | — |

Модель **не может**: пропустить стадию, смягчить гейт, промоутнуть персону,
потратить бюджет сверх лимита, трогать прод-креды, править код Workshop.
Всё это — механика. Модель **может**: предлагать переходы, патчи, новые драйвы,
диагнозы — всё через tool-API с валидацией.

## 2. Роли модели (микро-задачи)

Каждая роль = узкий контракт: вход (curated evidence), выход (JSON-схема),
проверка (механика). Температура 0–0.2, контекст ≤ 8k токенов на вызов.

| Роль | Вход | Выход (схема) | Кто проверяет |
|---|---|---|---|
| **Classifier** | drift report (машиночит.) + срез human-diff | `{class: TRIVIAL\|MINOR\|MAJOR\|BREAKING, evidence: [artifact_id:span], confidence: 0..1}` | сборка: механические правила дают класс для 90% диффов; LLM — только спорные; evidence-ссылки валидируются на существование |
| **Hypothesizer** | drift report + текущая персона (срез) | `{patch: unified-diff к TOML, rationale, risk_notes}` | lint (запрещённые комбинации бет/заголовков) → oracle (replay на upstream) → canary |
| **Drive-Author** | новый request-kind в MAJOR-диффе + примеры из корпуса | `{drive.toml: сид-промпты, ожидаемые request-kind,}` | прогон драйва: форма запросов обязана воспроизвестись; coverage-гейт стадии capture |
| **Diagnostician** | упавший ран: stderr, артефакты, история ретраев | `{hypothesis: enum сетевых/кодовых/данных/среды, next_action: enum, patch?: diff}` | следующий ран: предсказание либо сбылось, либо ретрай с другим next_action (≤ N раз) |
| **Reporter** | финальные артефакты (машиночит.) | прозой только связки; все числа — подстановки из схемы | числа берутся из артефактов движком, модель только фразеология |

Ключевой паттерн: **числа и факты пишет движок, модель пишет связки и суждения.**
Отчёт «готов к промоушену» генерится шаблоном, куда модель подставляет связный
текст между машинно-проверенными блоками.

## 3. Tool-API модели (всё, что она «руки»)

```
stage.run(name, params)         # запустить стадию Workshop; движок сам применит гейты
artifact.read(id, span)         # читать срез артефакта (никогда весь корпус)
persona.propose_patch(diff)     # предложить патч; применяется только после lint
oracle.request(sample_pct)     # запросить oracle-прогон (бюджет-гард режет сверх лимита)
drive.propose(toml)             # предложить новый драйв
checklist.state()               # текущее состояние рана, что закрыто, что нет
question.ask(text)              # эскалация человеку (пауза рана)
```

- `persona.propose_patch` = **minimal-diff** (unified diff), не регенерация файла:
  галлюцинация физически не может переписать то, чего нет в контексте.
- Никакого `shell_exec` у модели нет. Вообще. Стадии исполняет движок.
- Каждому tool-вызову — лог и артефакт: реплей полного рана возможен без модели.

## 4. Anti-hallucination механика (7 правил)

1. **Grammar-constrained decoding**: каждый вызов — через llama-server с
   `json_schema` (GBNF). Схемо-невалидный выход невозможен синтаксически.
2. **Citations checked**: каждое `evidence` поле — ссылка на artifact_id+span;
   движок проверяет существование и подсвечивает модели расхождения в ретрае.
3. **Grounding pack**: модель видит только curated-срез (какие именно строки диффа,
   какие заголовки), собранный движком под микро-задачу. Никогда — сырой корпус.
4. **Deterministic gates cannot be skipped**: TRIVIAL-автомерж, oracle, canary —
   код. Модель может предложить «считаю MAJOR → ревью» или «MINOR → полный oracle»,
   но не может вместо oracle.
5. **Every hallucination is testable**: таблица ролей — у каждого выхода есть
   механический детектор лжи (lint/oracle/прогон драйва/сбывшийся прогноз).
   Незакрываемых моделью зон нет.
6. **Retry budgets + divergence escalation**: максимум 3 ретрая на микро-задачу,
   максимум 2 replan-цикла на ран. Дальше — чекпоинт + `question.ask` человеку:
   «застрял на X, вот 3 варианта, выбери». Зацикливание = эскалация, не фантазия.
7. **Confidence routing**: `confidence < 0.7` → консервативный путь (более строгий
   класс, полный oracle, ревью человеком). Для 27B это дешёвая страховка.

## 5. Петля автономии: от «вот бинарь» до «подтверждаешь?»

```
человек: goal(binary, subscription) ──► AUTOPILOT loop:
  1. stage.run(acquire) ─── бинарь-бандл, хэши
  2. stage.run(drive-capture) ─── corpus-снапшот, coverage-гейт
  3. stage.run(diff) ─── drift report
  4. Classifier(diff)  ──[TRIVIAL: авто-патч]──► Hypothesizer ──► lint
     └─[MINOR/MAJOR]──► Hypothesizer ──► lint ──► (G1 человеку только если MAJOR)
  5. stage.run(oracle) ─── бьётся бюджет-гард; fail → Diagnostician → fix → повтор ≤2
  6. stage.run(canary) ─── SLO-окно
  7. Reporter: «Бинарь А с подпиской А1 готов к промоушену. Класс: MINOR.
     Дифф: +1 бета (X), версии строк, oracle 388/390 ok, canary 2ч 0 отклонений.
     Подтверждаешь?»
  8. человек: да ──► promote (атомарный swap, подпись) ──► hot-swap в прод
```

То же для PO (новый провайдер — больше роли Hypothesizer/Drive-Author, G1 обязателен)
и CO (новые подписки — почти без модели: логины/burn-in механические, Reporter
сводит метрики probation).

Checkpointing: состояние рана персистится (артефакты + решения модели + tool-лог);
краш/рестарт Mac Studio → ран продолжается с того же места, модель получает digest.

## 6. Почему именно так для 27B

- Задачи узкие и доменные: интерпретация структурного диффа, патч TOML на десяток
  строк, диагноз по stderr. Это не open-ended coding — это категория, где 27B
  с жёсткой схемой надёжен.
- Контекст на вызов маленький (grounding pack ≤ 8k): 27B не тонет.
- Скорость не критична: пайплайн и так идёт часами (capture, burn-in, canary-окна);
  инференс локальный, бесплатный, приватный — корпус не покидает Mac Studio.
- Abliterated-модель без отказов удобна для автономии; её «расхлябанность»
  компенсируется грамматиками и гейтами, а не промптами.

## 7. Чего модель не заменяет

- Реверс-интуицию при BREAKING (что имел в виду вендор) — она предложит гипотезу,
  но решение за человеком после G1.
- Выбор стратегий бюджета (сколько sacrificial-кредов жечь на oracle) — конфиг.
- Этику/ToS-решения — человек.

## 8. Фазы

| Фаза | Что | Мерило успеха |
|---|---|---|
| A1 | Reporter + Classifier в PB-пайплайне (модель в двух ролях, остальное ручное/механика) | 10 PB-ранов без человеческих правок классификации |
| A2 | + Hypothesizer (TRIVIAL/MINOR патчи персон) | 10 авто-мержей, 0 откатов после canary |
| A3 | + Diagnostician (авто-фиксы упавших ранов) | доля ранов, дошедших до Reporter без человека ≥ 80% |
| A4 | полный AUTOPILOT (Drive-Author, PO-поддержка) | PO-провайдер доведён до промо с ≤ 2 вопросами |

## 9. Открытые вопросы

1. One-shot vs. few-shot промпты ролей: пилот покажет; few-shot с историческими
   диффами CPA — готовый датасет.
2. Нужен ли второй «критик»-вызов (модель ревьюит свой патч) или хватает lint+oracle
   (моя ставка: хватает, лишний вызов только добавит галлюцинаций).
3. Оценка стоимости в токенах на ран (для планирования очередей на одном инстансе).
